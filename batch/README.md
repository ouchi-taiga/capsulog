# batch

メーカーからデータを収集して D1 に取り込む。日次で1回実行する。

Workers ではなく GitHub Actions で動かす。奇譚クラブの953件を1秒間隔で回すと約16分かかり、Workers の CPU 時間に収まらないため。

## 実行

```bash
uv run batch/main.py                 # 全メーカー。日次モード
uv run batch/main.py --maker kitan   # 1社だけ
uv run batch/main.py --full          # 全件の詳細を取り直す。初回用
uv run batch/main.py --dry-run       # D1 に書き込まない
uv run batch/main.py --limit 5       # 詳細取得を5件まで。検証用
```

書き込み先は環境変数 `D1_TARGET` で選ぶ。

| 値 | 先 |
|---|---|
| `local`（既定） | 手元の D1。`web/.wrangler/` の SQLite |
| `remote` | 本番の D1。`CLOUDFLARE_API_TOKEN` が要る |

**既定はローカル。** 手元での実行が誤って本番に書かないようにするため。
本番に書くのは GitHub Actions で、そちらに `D1_TARGET=remote` を設定する。

日次モードで詳細を取りに行くのは、新規の商品と発売が2ヶ月以内に迫った商品だけ。
発売済みの商品は変わらないため取り直さない。

## 日次実行

`.github/workflows/collect.yml` が毎朝5時（JST）に本番へ取り込む。
リポジトリの secret に `CLOUDFLARE_API_TOKEN` を登録しておく。

手動で回すときは GitHub の Actions タブから workflow_dispatch で実行する。
`full` を有効にすると全件を取り直す。

## 対象メーカー

| メーカー | 件数 | 取得方法 |
|---|---|---|
| 奇譚クラブ | 955 | サイトマップで一覧、詳細ページをパース |
| ターリン | 616 | API のみ |
| タカラトミーアーツ | 約47/月 | 月別カレンダーで一覧、詳細ページをパース |
| Qualia | 数百 | HTML で一覧、詳細ページをパース |
| パレード | 100 | カテゴリ一覧をページングし、詳細ページをパース |

**バンダイからは取らない。** 利用条件が自動取得を禁じている。

ターリン以外は一覧に発売月と全何種が無いため、商品ごとに詳細を取りに行く。

## 守ること

- リクエストは**1秒以上あける**
- User-Agent にサービス名と連絡先を入れる
- **商品説明文と画像を保存しない。** 事実情報のみを扱う
- 出典として公式ページの URL を必ず入れる
- 1社が失敗しても他社は続行する
- 触るのは `origin = 'batch'` の行だけ。運営の手入力分に触れない

## コードの書き方

- 標準ライブラリのみ。依存を増やさない
- 関数には docstring を書く。PEP 257 に従い、要約は開きクォートと同じ行に置く
- 流れが読み取りにくい処理には、何をしているかと、なぜそうしたかを書く
- 処理を見ればわかることは書かない

## 取り込み前の検証

壊れたデータで上書きしないため、取り込む前に検証する。通らなければそのメーカーは中止し、前回のデータを残す。

| 検証 | 中止する条件 |
|---|---|
| 件数 | 前回より3割以上減った |
| 価格 | 100〜2,000円の範囲外が1割を超えた |
| 全何種 | 1〜30の範囲外が1割を超えた |
| 発売月 | 過去30年〜未来2年の範囲外が1割を超えた |
| 欠損率 | 前回から20ポイント以上悪化した |

件数の判定は、全件が一覧に載る奇譚クラブとターリンとパレードだけで行う。
欠損率の判定は、全件を見ないと意味がないため全件モードだけで行う。

ターリンの発売月は常時8%前後欠損する。欠損そのものは異常として扱わない。

中止したときは理由と判定に使った数値をログに残す。通知は作らない。

## ログ

stdout と `batch/logs/` の2箇所に1行ずつ流す。

| 出力先 | 用途 |
|---|---|
| stdout | GitHub Actions のジョブログに90日残る |
| `logs/info.log` | 手元の実行をすべて追記 |
| `logs/error.log` | WARNING 以上だけ追記。問題の有無を先に見る |

`logs/` はコミットしない。

```text
2026-08-31 01:21:05 INFO    main.py:189 [kitan] 完了 listed=953 fetched=41 changed=3 missing_ym=0 elapsed=52s
```

- 時刻は日本時間。発売月の扱いと揃える
- 数値は `key=value` で書く。目で読めて、grep でも拾える
- レベルは3つ。INFO が正常の流れ、WARNING が商品単位の取りこぼし、ERROR が中止と失敗

| 見るべき値 | 意味 |
|---|---|
| `listed` | 一覧に載っていた件数。急減は取得の壊れ |
| `changed` | 普段は数件。全件変わったら構造変化を疑う |
| `missing_ym` | 発売月の欠損。ターリンは常時8%前後 |
