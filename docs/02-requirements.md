作成日: 2026-08-30

## 2. プロダクト概要

### 2.1 一行説明

メーカー横断のカプセルトイ発売カレンダーと、ラインナップ単位のコレクション管理サービス。

### 2.2 解決する課題

| 課題 | 現状の解決手段 | その問題点 |
|---|---|---|
| 新作がいつ出るか分からない | メーカー公式サイトを個別に巡回 | メーカーが約70社。横断して見る手段がない |
| 買い逃す | Xの情報アカウントをフォロー | 流れて消える。関係ない情報も大量に来る |
| 何を持っているか分からない | 記憶、または汎用メモアプリ | 「全5種中3種」という単位で管理できない |
| ダブりが処理できない | Xで交換募集、メルカリ出品 | 目視で照合するしかない |

### 2.3 やらないこと

調査で勝てないと判明した領域。意図的に作らない。

| やらないこと | 理由 |
|---|---|
| 店舗別の入荷日予測・入荷通知 | 情報が構造的に存在しない。精度を約束できず必ずクレームになる |
| 設置場所検索・在庫検索 | 公式3社が無料提供済み。POS連動は個人開発では再現できない |
| 配送・決済の仲介、エスクロー | 運営コストが無限大。個人運営で当事者間トラブルは裁けない |
| リアルタイムチャット | 実装・運用が重い。既存のSNSに委ねる |
| 本人確認・評価システム | 初期スコープ外 |

### 2.4 名称と商標

サービス名は**カプセログ**。カプセル + ログで、カプセルトイを記録するという意味。

**「ガチャ」「ガチャガチャ」「ガシャポン」は名称・表記に使わない。** いずれもメーカーの登録商標であるため。

| 語 | 権利者 | 扱い |
|---|---|---|
| ガチャ / GACHA | タカラトミーアーツ（登録第4106448号） | 使わない |
| ガチャガチャ | バンダイ | 使わない |
| ガシャポン | バンダイ | 使わない |
| **カプセルトイ** | — | **使う。** 権利者2社とも一般名詞として使い分けている |

これは収集対象のメーカーへの心証にも関わる。**サービス名、画面上の文言、リポジトリの説明文のいずれにも使わない。**

## 3. ターゲットユーザー

### 3.1 プライマリ

**20〜30代女性の専門店来店層。**

- 20代女性の購入率 54.1%、30代女性 51.7%
- 20〜30代女性の専門店来店経験 78.6%（前年 69.6%）
- ガチャガチャの森利用者の約6割が女性
- 「SNS映え」を魅力とする回答が 7.1% → 12.5% と倍増

SNSでの獲得と相性が良い。

### 3.2 セカンダリ

1回1,000円以上使う高支出層。全年代で15〜20%、約230〜310万人。

### 3.3 想定しないユーザー

- 年数回しか買わないライト層。管理する動機がない
- 転売目的の利用者。規約で明示的に排除する

## 4. フェーズ構成

フェーズ3はフェーズ2のデータがないと動かず、フェーズ2はフェーズ1の商品DBがないと作れない。順序に技術的な必然性がある。

| フェーズ | 期間目安 | 内容 | 課金 |
|---|---|---|---|
| 1 | 1〜2ヶ月 | メーカー横断の発売カレンダー | 無料 |
| 2 | 2〜3ヶ月目 | 「気になる」登録＋コレクション管理 | 無料 |
| 3 | 4ヶ月目〜 | ダブり交換マッチング | ここで課金 |

収益が立つのは早くて開発開始から半年後。フェーズ1・2は競合が無料のため無料で提供する。

## 5. フェーズ1: 発売カレンダー

### 5.1 目的

- 動くものを最速で作り、データが本当に取れるか実証する
- 開発者自身が毎日使う
- フェーズ2以降の土台となる商品DBを構築する

### 5.2 機能要件

| ID | 機能 | 優先度 | 備考 |
|---|---|---|---|
| F1-1 | メーカー横断の新作一覧表示 | 必須 | 発売月でグルーピング |
| F1-2 | 発売月でのフィルタ | 必須 | 今月/来月/再来月 |
| F1-3 | メーカーでのフィルタ | 必須 | |
| F1-4 | キーワード検索 | 必須 | 商品名 |
| F1-5 | 商品詳細表示 | 必須 | 全何種、価格、ラインナップ |
| F1-6 | 公式サイトへのリンク | 必須 | 出典明示を兼ねる |
| F1-7 | 価格帯フィルタ | 任意 | 300/400/500円 |

### 5.3 対象メーカー

奇譚クラブ、ターリン、バンダイの3社で開始する。合計約2,000商品。

タカラトミーアーツと Qualia はフェーズ1完了後に追加する。

### 5.4 表示上の制約

| 項目 | 扱い |
|---|---|
| 発売日 | 月単位まで。日単位では表示しない |
| 発売月が不明な商品 | 「発売月未定」として扱い、確定分と混ぜない |
| バンダイの「未定」 | 月は表示し、日が未定であることを併記する |
| ラインナップ名 | 奇譚クラブのみ表示される |
| 商品画像 | 表示しない |
| 商品説明文 | 表示しない |

### 5.5 非機能要件

| 項目 | 要件 |
|---|---|
| 表示速度 | 一覧表示 1秒以内 |
| 対応ブラウザ | モダンブラウザ最新2バージョン |
| モバイル対応 | 必須。スマホでの利用が主 |
| インフラコスト | 月額0円。無料枠内 |
| 可用性 | ベストエフォート。SLAなし |
| データの正しさ | 収集が壊れたときは、古いデータを残す。誤ったデータで上書きしない |

## 6. フェーズ2: コレクション管理

### 6.1 中核となる差別化点

**ラインナップ単位の管理。** 調査で判明した最大の空白。

```text
「○○シリーズ 全5種」
  タイプA      所持 2個（1個ダブり）
  タイプB      所持 1個
  タイプC      未所持
  タイプD      所持 1個
  シークレット   未所持
  → コンプ率 60%（3/5）、ダブり 1個
```

海外の Blind Box Tracker / Collectsy はこの仕組みを持つが日本のカプセルトイに非対応。日本のサービスは情報を持つが管理機能がない。この交差点を取る。

### 6.2 機能要件

| ID | 機能 | 優先度 |
|---|---|---|
| F2-1 | 「気になる」登録 | 必須 |
| F2-2 | 発売月が近づいたら通知 | 必須 |
| F2-3 | 所持・未所持の記録 | 必須 |
| F2-4 | ダブり個数の記録 | 必須 |
| F2-5 | コンプ率の表示 | 必須 |
| F2-6 | ユーザー投稿写真 | 任意 |
| F2-7 | コレクションのシェア画像生成 | 任意 |

### 6.3 通知の内容

通知するのは「気になる登録した商品の発売月です」。**入荷情報は持っていないため、そこを約束しない。**

### 6.4 前提

ラインナップ名が取れるのは奇譚クラブのみ。**このフェーズは当面その1社の商品でしか成立しない。**

他社商品でもコンプ率を管理できるようにするには、ラインナップをユーザー投稿で補うか、対象メーカーを増やす必要がある。フェーズ1のデータを見てから判断する。

## 7. フェーズ3: ダブり交換マッチング

### 7.1 なぜここが課金ポイントになるか

| 理由 | 説明 |
|---|---|
| メーカーが構造上やれない | 交換成立は自社売上を食う |
| 無料の管理アプリにもない | 既存アプリは売買のマーケットプレイスであって交換マッチングではない |
| 需要が実証済み | メルカリに週16,500件のカプセルトイ取引。SNSで交換募集が活発 |
| 仕組みが実証済み | 海外 Collectsy が同機能を実装。日本商品に非対応なだけ |
| 機能でなく機会への課金 | 無料競合と正面衝突しない |

### 7.2 スコープの限定

**マッチングだけ作り、その先は作らない。**

| 要素 | 作るか |
|---|---|
| ダブり・欲しい物の登録 | 作る |
| マッチング計算 | 作る |
| マッチ結果の提示 | 作る |
| 連絡手段 | 作らない。外部のSNSに委ねる |
| チャット | 作らない |
| 評価・本人確認 | 作らない |
| 配送・決済仲介 | 作らない |

手抜きではなく意図的な判断。個人運営で当事者間トラブルを裁くのは不可能なため、裁かない構造にする。

### 7.3 課金設計

| プラン | 価格 | 内容 |
|---|---|---|
| 無料 | 0円 | カレンダー全機能、コレクション管理、マッチ相手の人数のみ表示 |
| 有料 | 月額350〜480円 | マッチ相手の詳細表示、連絡先の開示、マッチ数無制限 |

同ジャンルの相場が月額350円。**500円が上限、1,000円は非現実的。**

年額プランを併設する。

## 8. リスク

| リスク | 影響度 | 対応 |
|---|---|---|
| 集客ができない | 高 | 最大のリスク。MAU 3,000〜12,000 が必要。SNSでの発信を開発と並行して行う |
| 開発者の興味の減衰 | 高 | フェーズ1を自分が毎日使うものにする |
| 無料競合の圧力 | 高 | 管理機能は無料提供。課金は交換マッチングに限定 |
| 収集の破損 | 中 | 取り込み前に件数と値を検証し、異常なら当該メーカーのみ中止して前回データを保つ |
| メーカー規約の変更 | 中 | 予告なく変更される。規約とrobots.txtを半年に1度再確認する |
| ラインナップが1社しか取れない | 中 | フェーズ2の前提。ユーザー投稿で補うか対象を増やす |
| 画像の権利問題 | 中 | フェーズ1は画像を持たない。フェーズ2でユーザー投稿に移行 |
| 公式の機能拡張 | 中 | メーカー横断とコレクション管理は公式が構造上やりにくい |
| 交換トラブル | 中 | 仲介しない設計。規約で当事者間の責任を明示 |

## 10. 判断の記録

| 判断 | 理由 |
|---|---|
| 入荷情報を主軸にしない | 情報が構造的に存在しない。先行者も失敗している |
| 在庫・設置場所検索をやらない | 公式3社が無料提供済み |
| 日単位の発売日を持たない | 全メーカーが月単位までしか公開していない |
| フェーズ1で画像を持たない | 版権物であり再配布はできない |
| 交換のチャットを作らない | 運用コストが重い。既存のSNS文化に委ねる |
| 価格を500円未満にする | 同ジャンル相場が350円 |
| PWAで始める | Mac不要、審査不要、iOS 16.4以降でPush対応 |
| サービス名に「ガチャ」を使わない | メーカーの登録商標のため |
