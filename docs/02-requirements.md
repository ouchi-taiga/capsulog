作成日: 2026-08-30

## 2. プロダクト概要

### 2.1 一行説明

カプセルトイの発売カレンダーと、撮影した戦利品を飾るコレクション棚、ダブりの交換マッチング。

### 2.2 解決する課題

| 課題 | 現状の解決手段 | その問題点 |
|---|---|---|
| 新作がいつ出るか分からない | メーカー公式サイトを個別に巡回 | メーカーが約70社。横断して見る手段がない |
| 買い逃す | Xの情報アカウントをフォロー | 流れて消える。関係ない情報も大量に来る |
| 集めたものを見せる場がない | Xに写真を投稿 | 流れて消える。コレクションとしての一覧性がない |
| ダブりが処理できない | Xで交換募集、メルカリ出品 | 目視で照合するしかない。相手探しに手間がかかる |

### 2.3 やらないこと

| やらないこと | 理由 |
|---|---|
| 店舗別の入荷日予測・入荷通知 | 情報が構造的に存在しない。精度を約束できず必ずクレームになる |
| 設置場所検索・在庫検索 | 公式3社が無料提供済み。POS連動は個人開発では再現できない |
| アプリ内チャット | 電気通信事業法の「他人の通信の媒介」に該当し、届出対象になり得る。連絡は X に委ねる |
| 配送・決済の仲介、エスクロー | 金銭を預からない。個人運営で当事者間トラブルは裁けない |
| 値付け・相場表示・売買機能 | 物々交換のみ。転売の場にしない |
| 本人確認 | 初期スコープ外 |

### 2.4 名称と商標

サービス名は**カプセログ**。カプセル + ログで、カプセルトイを記録するという意味。

**「ガチャ」「ガチャガチャ」「ガシャポン」は名称・表記に使わない。** いずれもメーカーの登録商標であるため。

| 語 | 権利者 | 扱い |
|---|---|---|
| ガチャ / GACHA | タカラトミーアーツ（登録第4106448号） | 使わない |
| ガチャガチャ | バンダイ | 使わない |
| ガシャポン | バンダイ | 使わない |
| **カプセルトイ** | — | **使う。** 権利者2社とも一般名詞として使い分けている |

これは収集対象のメーカーへの心証にも関わる。**サービス名、画面上の文言、リポジトリの説明文のいずれにも使わない。**

### 2.5 画像の方針

**メーカーの公式画像は保存も表示もしない。** 商品画像は全社とも版権物で、メーカー自身が権利者の許諾を得て使っている。メーカーに許諾を求めても又貸しになるため出せない。

**画像はすべてユーザーが撮影した現物写真。** 撮影者に著作権があり、権利問題が生じない。

## 3. ターゲットユーザー

### 3.1 プライマリ

**20〜30代女性の専門店来店層。**

- 20代女性の購入率 54.1%、30代女性 51.7%
- 20〜30代女性の専門店来店経験 78.6%（前年 69.6%）
- 「SNS映え」を魅力とする回答が 7.1% → 12.5% と倍増

集めたものを見せたい層であり、棚の共有画像と相性が良い。

### 3.2 セカンダリ

1回1,000円以上使う高支出層。全年代で15〜20%、約230〜310万人。ダブりが多く発生する層でもある。

### 3.3 想定しないユーザー

- 年数回しか買わないライト層。管理する動機がない
- 転売目的の利用者。金額要素を持たない設計と規約で排除する

## 4. フェーズ構成

交換は棚のデータ（ダブりの印）がないと動かず、棚はカレンダーの商品マスタがあるほど滑らかになる。順序に必然性がある。

| フェーズ | 期間目安 | 内容 | 課金 |
|---|---|---|---|
| 1 | 1〜3ヶ月 | 発売カレンダー＋コレクション棚 | 無料 |
| 2 | 4〜5ヶ月目 | ダブり交換マッチング | 無料 |
| 3 | 6ヶ月目〜 | 棚のプレミアム機能・マッチングの高度化 | ここで課金 |

棚は単体で価値が成立する。交換の相手が集まる前でも使われることが、コールドスタートへの答えになる。

## 5. フェーズ1: 発売カレンダーとコレクション棚

### 5.1 目的

- 動くものを最速で作り、開発者自身が毎日使う
- 棚の共有画像を X 拡散の主導線にして、ユーザーを集める
- フェーズ2の土台（商品マスタと、ダブりの印がつく棚）を作る

### 5.2 機能要件: カレンダー

| ID | 機能 | 優先度 | 備考 |
|---|---|---|---|
| F1-1 | メーカー横断の新作一覧表示 | 必須 | 発売月でグルーピング |
| F1-2 | 発売月でのフィルタ | 必須 | 今月/来月/再来月 |
| F1-3 | メーカーでのフィルタ | 必須 | |
| F1-4 | キーワード検索 | 必須 | 商品名 |
| F1-5 | 商品詳細表示 | 必須 | 全何種、価格、ラインナップ |
| F1-6 | 公式サイトへのリンク | 必須 | 出典明示を兼ねる |
| F1-7 | 価格帯フィルタ | 任意 | 300/400/500円 |

### 5.3 機能要件: 棚

| ID | 機能 | 優先度 | 備考 |
|---|---|---|---|
| F1-8 | 撮影写真の自動切り抜き | 必須 | 端末内で処理。生画像をサーバーに送らない |
| F1-9 | 切り抜きの手動リタッチ | 必須 | 自動で失敗したときの逃げ道 |
| F1-10 | テーマ什器への配置 | 必須 | アクリルケース風・棚風など |
| F1-11 | 共有画像の生成 | 必須 | X 投稿用。拡散の主導線 |
| F1-12 | 商品マスタへの紐付け | 任意 | シリーズ・アイテムを選択。フェーズ2のマッチ精度に効く |
| F1-13 | コンプ率の表示 | 任意 | ラインナップが取れる奇譚クラブのみ成立 |

### 5.4 対象メーカー

| メーカー | 件数 | 扱い |
|---|---|---|
| 奇譚クラブ | 953 | 自動収集 |
| ターリン | 616 | 自動収集 |
| タカラトミーアーツ | 約47/月 | 自動収集。発売時期が週単位で取れる唯一の社 |
| Qualia | 数百 | 自動収集 |
| バンダイ | — | **対象外。** 利用条件が自動取得を明示的に禁じている。運営の手入力で載せる余地だけ残す |

### 5.5 表示上の制約

| 項目 | 扱い |
|---|---|
| 発売日 | メーカーが公開する粒度のまま。月・旬・週。日単位では表示しない |
| 発売月が不明な商品 | 「発売月未定」として扱い、確定分と混ぜない |
| ラインナップ名 | 奇譚クラブのみ表示される |
| 公式の商品画像 | 保存も表示もしない |
| 棚の写真 | ユーザーが撮影したもののみ |

### 5.6 非機能要件

| 項目 | 要件 |
|---|---|
| 表示速度 | 一覧表示 1秒以内 |
| 対応ブラウザ | モダンブラウザ最新2バージョン |
| モバイル対応 | 必須。スマホでの利用が主 |
| インフラコスト | 月額0円。無料枠内 |
| 可用性 | ベストエフォート。SLAなし |
| データの正しさ | 収集が壊れたときは、古いデータを残す。誤ったデータで上書きしない |

## 6. フェーズ2: ダブり交換マッチング

### 6.1 中核となる差別化点

**棚に飾る行為が、そのまま出品の整備を兼ねる。** 切り抜き画像とシリーズタグを持つ棚のアイテムにダブりの印をつけるだけで、交換待機列に載る。「みんなのためのデータ入力」をユーザーにさせない。

### 6.2 機能要件

| ID | 機能 | 優先度 | 備考 |
|---|---|---|---|
| F2-1 | 譲（ダブり）と求（欲しい物）の登録 | 必須 | 棚のアイテムから、またはフリーテキスト |
| F2-2 | 相互一致のマッチング | 必須 | 譲と求が双方向に一致 |
| F2-3 | ホームエリア | 必須 | 行ける場所を事前登録。重なる人同士だけマッチ |
| F2-4 | X ハンドルの相互開示 | 必須 | マッチ成立時のみ・相互同意で |
| F2-5 | 通報と出品取り下げ | 必須 | 権利者からの削除申立て窓口を兼ねる |
| F2-6 | 交換完了時の相互評価 | 任意 | エア出品対策 |

### 6.3 ユーザー入力の扱い

**ユーザー入力は商品マスタに入れない。** マッチング用のデータとしてのみ保存する。

- マスタにある商品は選択で紐付ける。入力時にインクリメンタル検索で候補を出す
- マスタに無い商品（バンダイ等）はフリーテキストで登録できる
- フリーテキスト同士・フリーテキストとマスタの照合は曖昧一致で行う。**自動で確定せず「同じものかも」と候補を提示するまで。** 確定するのは人

### 6.4 連絡手段

マッチ成立後は登録時同意済みの X ハンドルを相互開示し、以降のやり取りは X 上で行う。**アプリ内チャットは作らない。**

現地での対面交換を基本形として推奨する。その場で現物を確認して手渡すため、騙し取られる構造がない。

### 6.5 転売対策

完全防止ではなく「転売業者にうまみがない場」を目指す。

- 値付け・金額欄・相場表示を一切持たない
- 同時出品数・月間交換回数に上限を設ける
- 対面交換主軸のため、量を捌く業態にはスケールしない

### 6.6 エア出品対策

- 棚への登録は取り締まらない。入り口の気軽さを優先する
- **交換出品の瞬間にのみゲートを設ける。** 画像の重複検出、新規アカウントの初回出品数制限

## 7. フェーズ3: 収益化と高度化

### 7.1 課金設計

**交換からは徴収しない。** 金銭を仲介しない方針と整合させる。

| プラン | 価格 | 内容 |
|---|---|---|
| 無料 | 0円 | カレンダー全機能、棚（登録数に上限）、交換 |
| プレミアム | 月200〜300円 | 棚の登録無制限、カスタムテーマ、バックアップ |

### 7.2 高度化

- テキスト embedding による曖昧マッチの精度向上
- 画像類似検索。表記ゆれ・未登録品のマッチングと、出品画像の重複検知に使う
- カプセルトイ専門店への送客・交換会イベント連携

## 8. リスク

| リスク | 影響度 | 対応 |
|---|---|---|
| 集客ができない | 高 | 最大のリスク。棚の共有画像を拡散の弾にする。SNS発信を開発と並行して行う |
| 交換のコールドスタート | 高 | 棚が単体で価値を持つ設計にし、ユーザーが貯まってから交換を開く |
| 開発者の興味の減衰 | 高 | フェーズ1を自分が毎日使うものにする |
| 切り抜きの品質 | 中 | 撮影ガイドで底上げし、手動リタッチの逃げ道を用意する |
| メーカー規約の変更 | 中 | 規約とrobots.txtを半年に1度再確認する。禁止されたメーカーは収集を止め、ユーザー入力に切り替えられる構造にする |
| エア出品 | 中 | 出品時のゲートと対面交換で実害を抑える |
| 交換トラブル | 中 | 仲介しない設計。規約で当事者間の責任を明示 |
| 収集の破損 | 中 | 取り込み前に件数と値を検証し、異常なら当該メーカーのみ中止して前回データを保つ |

## 10. 判断の記録

| 判断 | 理由 |
|---|---|
| 入荷情報を主軸にしない | 情報が構造的に存在しない。先行者も失敗している |
| 在庫・設置場所検索をやらない | 公式3社が無料提供済み |
| バンダイを収集対象にしない | 利用条件が自動取得を明示的に禁じている |
| 公式の商品画像を使わない | 版権物であり、メーカー自身が又借りの立場。ホットリンクも各社が掲示を禁じている |
| 画像はユーザー撮影のみ | 撮影者に著作権があり、権利問題が生じない |
| ユーザー入力をマスタに入れない | マスタの品質を守る。入力は自分の出品のためだけに行われる |
| 曖昧マッチは候補提示まで | 交換は最後に人間が現物確認する。自動確定の精度を追わない |
| 日単位の発売日を持たない | 日単位まで公開するメーカーがない。粒度は月・旬・週 |
| アプリ内チャットを作らない | 電気通信事業法の届出対象になり得る。既存のSNSに委ねる |
| 金銭を扱わない | エスクロー・相場表示を持たず、転売の場にしない |
| 切り抜きを端末内で行う | サーバーコストがゼロになり、生画像がユーザーの端末から出ない |
| 課金は棚のプレミアムに置く | 交換から徴収すると金銭仲介を避ける方針と衝突する |
| PWAで始める | Mac不要、審査不要。iOS ネイティブは需要を見てから |
| サービス名に「ガチャ」を使わない | メーカーの登録商標のため |
